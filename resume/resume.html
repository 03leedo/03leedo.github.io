2026.09 – 2026.11 · 6인 팀

카카오테크 캠퍼스 4기 2단계 · 웹 · Android 웹뷰 앱 배포(AWS EC2) · github.com/kakaotechcampus-4/ktc4-pusan-3

역할 — AI Agent(Activity · 놀이 추천) · AI 품질 평가 · 공공데이터 연동 · 커밋 300 · 머지 PR 68

  • Activity Agent 설계 · 구현. 놀이 기록 · 날씨 · 일정 · 근처 장소와 행사를 엮어 놀이를 최대 3개 추천합니다. 설계 문서부터 쓰고 구현했습니다 — 폴더 커밋 142개 중 116개, 단위 테스트 함수 696개.
  • 안전 판정을 모델 출력 바깥에. 위험 용어 사전 × 월령으로 막고, 알레르기는 후보의 음식 칸을 Food 메뉴 판정으로 거릅니다. 알레르기 이름은 모델에 보내지 않습니다. 알레르기 음식에 닿는 추천 17 → 3 (54케이스 로컬 실험), 시드 전수 회귀 테스트의 오탐 17 → 0.
  • 되돌리고 다시 설계. 근거 관련성 검사와 함께 바꾼 지시가 예시를 베낀 억지 추천을 40%로 늘려 되돌렸고(14%), 요청 기반 추천으로 다시 설계했습니다. 중앙 응답 12.3 → 9.0초, 20초 초과 run 9 → 2 (108 run). 코드로 막기 전에 후보 391개를 다른 모델로 판정하고 대조군 120개로 판정 모델을 검증했습니다.
  • 공공데이터 6종 연동. 기상청 단기 · 중기예보 · 자외선 · 특보, 에어코리아 대기질, TourAPI 행사 · 문화시설. 공원 · 도서관은 적재해 거리를 서버 안에서 계산합니다 — 보호자 좌표를 외부 API 로 보내지 않습니다.
  • 20초 예산 지키기. 캐시가 빈 첫 run 에서 행사 읽기를 날씨 조회와 동시에 시작하고 읽기 상한을 둬, Activity 전체 16.8–19.2 → 13.7–16.8초.
  • AI 품질 점검 하네스. 절대 규칙을 코드로 판정하는 불변식 14개 · 능력별 단발 프로브 · 일주일 시나리오 · 장애 점검표 40칸. 팀 기준선 — 절대 규칙 위반 0건 (147 run), 기획 시나리오 9/10 (3회 모두 통과), 장애 점검 39/40.
